# Evidence behind the checks

[Version française](evidence.fr.md)

Read on 2026-10-16. Nothing here copies a manifest or schema text: the repository ships a small schema tree extracted from a public file, and cites where it came from.

## The schema

`src/component_manifest_lint/schema.json` was generated by `tools/extract_schema.py` from the `Component` custom resource definition in the public Canvas repository, pinned to commit `c39da6340dbc`:
[oda-component-crd.yaml](https://github.com/tmforum-oda/oda-canvas/blob/c39da6340dbc/charts/oda-crds/templates/oda-component-crd.yaml). The repository declares Apache-2.0.

What that file says, and the rules built on it:

- Four versions are served: `v1beta2`, `v1beta3`, `v1beta4` and `v1` (M002). Only `v1` is marked as the storage version.
- Required fields are few: `name` and `specification` for core and security APIs, `name` for management APIs, `type` and `podSelector` for secrets management (M006). Most of the manifest is optional.
- Only two nodes keep unknown fields (`secretsManagement` and `status`). Everywhere else the schema is closed, which is why M001 reports unknown fields: they are not part of the published resource.
- Field types are declared (M012).

The claim that a cluster "will most likely drop" an unknown field follows from how Kubernetes treats structural schemas without the preserve-unknown-fields setting; it was not tested against a running cluster here.

## The public examples

Rules M003 and M009 come from two manifests in the public examples repository, pinned to commit `be11fd016144`: the [Product Inventory source manifest](https://github.com/tmforum-oda/reference-example-components/blob/be11fd016144/source/ProductInventory/test-instance.component.yaml) and the Party Management chart template. In both, the label `oda.tmforum.org/componentName` equals the component name and every exposed API path starts with `/` followed by that name. Two examples are thin evidence, which is why these rules are only `info`. The repository declares Apache-2.0.

Six other chart templates of that repository could not be parsed by the quick de-templating used here, so they were not used as evidence.

## Run on a real manifest

The Product Inventory source manifest above gives two `info` findings and nothing else: two specification URLs point at the `master` branch (M011). It has no warning or error.

## What this does not establish

Nothing here shows conformance, certification or acceptance by a live Canvas. M004, M005 and M011 are judgement calls, not requirements.
